# Security, Privacy and Secrets — Phased without Waiving Baselines

**S1 A hard release gate:** private Open Notebook native API and privileged UI; only Sunrise Vault Policy Layer reachable by Admin HTTPS; mandatory OPEN_NOTEBOOK_PASSWORD, encryption key, private DB credentials must be non-default, non-empty and available via approved Secret Store at startup or STOP. Native auth absence may skip password checks (observed in uploaded Open Notebook snapshot `api/auth.py`); thus native API must be network-isolated even with password. Database example `root:root` never permitted in deployed environments. Source→Shell→Notebook authoritative catalog and nonempty scoped search, download, preview and SSE checks **before any bytes/LLM context are sent**. Audit 401/403 and failure; backup key-restoration tested without committing key. Single Admin does not mean no security.

**S3 B:** separate Postgres/Supabase credentials/backup, school_id/course_id/actor_id/access_scope from first schema. `service_role` must not be in frontend or I. RLS is defence-in-depth only; DB role privileges and audit also apply. **S4 I:** no DB connection strings, strict A/B service allowlist, signed short-lived service tokens; durable operation state via B API and A journal; QUARANTINED on mismatch. **S7 B:** Gemini key stored server side masked; auth test, model access, quota and live call statuses distinct; no key in queue/log/frontend storage.

**S9 I:** evidence signed, time-bound, limited purpose/sources/excerpts, JWT/JWS-like payload validation plus issuer/audience/nonce/jti/exp/kid and binding+grant revision checks. Call I validation again immediately before B execution and before publishing if evidence status can change. Check A version/published/licence/permission; source excerpts are untrusted data, ignore prompt injection; no privileged tool calls based on retrieved text. No guarantees of atomic cross DB snapshots; fail closed on stale/revoked/unknown state.

**S17 B:** grade events INSERT-only to normal service roles, UPDATE/DELETE forbidden; correction has event/reason/CAS version and DB-enforced single writer ordering. **S22 B:** Staff identities/role/grants/revocation epoch; **S23 I:** teacher read-only A; per request grant & cache invalidation. **S25 B:** school-approved real PII gate. ## Public repository disclosure and incident response (2026-11-14)

The GitHub source and **all public commit history, PR discussions, Actions logs, job summaries, downloadable artifacts and forks** must be treated as externally readable. Never commit, paste or attach `.env` / `runtime.env`, credentials, PEM/SSH/private signing or restore keys, JWT/Bearer values, session cookies, CSRF tokens, admin/DB root passwords, school/student PII, licensed textbook originals, private backup/restore images, raw runtime logs, sensitive host paths or network identities. Synthetic fixture values must be clearly nonfunctional; hashes and redacted summaries are preferred. Avoid publishing exploit-ready details of unpatched vulnerabilities.

**Report suspected vulnerabilities privately:** use GitHub's repository **Security → Report a vulnerability** / private vulnerability reporting **only if enabled and visible**; otherwise contact the repository Owner through an independently verified private channel. Do **not** open a public issue/PR with a working exploit, credentials or identifying student content. Do not assume private vulnerability reporting is enabled without checking repository settings.

**Untrusted contributions:** external forks, pull requests, code, dependencies, workflow inputs and artifacts are untrusted. No secrets or privileged write tokens in fork PR jobs; avoid `pull_request_target`, unreviewed Actions, mutable third-party actions, workflow self-modification and automatic execution of untrusted code with privileged credentials. Existing Light CI runs only same-repository PRs and uses read-only contents permissions, reviewed immutable Actions SHAs and `persist-credentials: false`. The two approved Stage 1 workflows remain subject to the $0 Budget / Stop Usage limit and independent workflow review.

**Exposure response:** stop dissemination and privileged execution, preserve **redacted** incident metadata (affected path/commit/time/type, never the value), notify Owner privately, revoke/rotate the credential at its issuer, invalidate sessions/JWT signing keys if relevant, audit access and downstream copies/forks/artifacts, replace affected deployments, and verify revocation and regressions before reopening. Removing a file in a later commit does **not** erase public Git history, forks or Actions artifacts. History rewrite/force push, deletion, billing changes and production intervention require separate explicit authority and an incident plan. Public-source scanning is incomplete without provider secret scanning and full-history review; absence of findings is not a security certificate.
