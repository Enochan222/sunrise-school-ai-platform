# S1 — Secure A-only Vault Execution, No B Setup

1. Review source snapshot `open-notebook-main(1).zip` at pinned commit and chosen immutable images. Native middleware may skip auth if `OPEN_NOTEBOOK_PASSWORD` missing. Fail startup on required password, encryption key or DB credentials absent/default. Use private native Open Notebook API, worker, SurrealDB and file volumes; only Sunrise Vault API publicly reachable under Admin HTTPS/session. Protect direct database port and worker network.
2. Build **minimum** Content Shell Page with `content_shell_id` and unique `external_course_key` scoped by school/year/grade/subject, not a formal B Course. Only this UI can create a Notebook using private Adapter (deduplicated durable `creation_op`). No direct native Create/Delete, no public upstream shared password. Define Course vs Teaching Group granularity from ADR-012 for later B, without creating B tables here.
3. Upload Textbook/Notes/Past Papers (de-identified). Create Source Owner mapping and `sha256`/metadata. Before any search/download/preview/SSE/LLM context, check nonempty Shell Notebook Scope; after retrieval verify Source belongs to Shell, deny cross Source/IDOR. Raw upstream Route and empty Scope negative tests are hard release Gate.
4. Define basic original material retention/copyright/AI usage policy; Source Archive is not Delete. A-only DB+file/key consistent backup; isolated restore and file SHA/Source ID/provenance checks. Test same-idempotency-key retry after ACK loss, Worker restart, Secrets rotation/revocation. No fabricated time estimate — one-hour Spike optional exploration only.
5. Produce actual Staging URL, Git SHA, pinned image digest, all S1-AT statuses, HTTP negative traces, material Hash Manifest, A Restore evidence, Owner UAT + signoff. No B Postgres/Supabase, no I Cross-DB, no Teacher/Students/Generated Paper. If raw Open Notebook UI cannot be adequately fenced off, stop and implement reviewed private Gateway/fork before Release.
